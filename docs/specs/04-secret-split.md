# 04. 비밀 분리 빌드 — "안 보여주기"에서 "안 보내기"로

**선행 조건**: 명세 01·03 완료
**소유 파일**: `tools/build.mjs`, `web/template.html`, `web/src/data.js`,
`web/src/net.js`, `web/src/ui-net.js`, `tools/verify-ui.mjs`, `.gitignore`

## 왜 필요한가

명세 01은 비밀을 **렌더링 단계에서** 가렸습니다. 명세 03은 **세션 중 생기는 정보**를
점유자에게만 보내게 했습니다. 그런데 정작 지켜야 할 것 — 사전 제작 캐릭터 16명의
`secret` — 은 **여전히 모든 클라이언트의 HTML에 박혀 있습니다.**

```bash
$ node -e 'const c=require("./data/characters.json"),h=require("fs").readFileSync("web/index.html","utf8");
           console.log(c.filter(x=>h.includes(x.secret)).length + "/" + c.length)'
16/16
```

개발자 도구를 열거나 파일을 텍스트 편집기로 여는 순간 전부 읽힙니다.
[ADR-001의 단서](../adr/001-p2p-sync.md#단서--비밀-차단은-아직-절반만-이뤄졌다) 참고.

이게 왜 중요하냐면 — 이 비밀들은 **세션 중반에 터뜨리도록 설계된 장치**입니다.
"준은 그날 스승을 두고 도망쳤다", "레오는 릴리스의 가문을 몰락시킨 사냥에 가담했다".
시나리오 「역참-0」의 클라이맥스 증언 트랙은 이 비밀들이 그 순간까지 안 알려져 있다는
전제 위에 서 있습니다. 미리 읽히면 3시간을 쌓아 올린 장면이 무너집니다.

> 한 가지 분명히 해둘 것: 이건 보안 문제가 아니라 **연출 문제**입니다.
> 작정하고 뜯어보는 사람을 막는 게 목적이 아니라, 호기심에 개발자 도구를 열었다가
> 자기 세션을 스스로 망치는 일을 막는 게 목적입니다. 그래서 암호화는 과합니다 —
> 애초에 파일에 안 넣는 것으로 충분합니다.

## 설계

빌드를 둘로 쪼갭니다.

| 산출물 | 담기는 것 | 받는 사람 |
|---|---|---|
| `web/index.html` | 비밀 **없음**. 자리표시자만 | 전원 (플레이어·GM 공용) |
| `web/secrets.json` | 16명의 `secret`만 담은 작은 파일 | **GM만** |

- 기본 빌드는 비밀을 뺍니다. 아무나 받아도 안전합니다.
- GM은 입장 후 `secrets.json`을 **가져오기**로 읽어들입니다
  (명세 03이 만든 상태 가져오기 UI와 같은 자리).
- GM이 비밀을 갖고 있으면, P2P로 **각 점유자에게 자기 캐릭터 비밀만** 보냅니다.
  이게 명세 03 §4가 원래 하려던 일입니다.
- GM이 `secrets.json`을 안 읽어도 세션은 정상 진행됩니다. 비밀 칸이 비어 있을 뿐입니다.

`secrets.json`은 `data/characters.json`에서 빌드 시 자동 생성하므로 따로 관리하지
않습니다. **저장소에는 커밋하되**(원본 자료의 일부이므로) 빌드 산출물 디렉터리
기준으로는 GM에게만 배포되는 파일이라는 점을 README에 명시하세요.

### 오프라인 우선 원칙과 충돌하지 않는가

하지 않습니다. 네트워크 없이도 도구는 100% 동작하고, GM 단말은 파일 하나를
**로컬에서** 읽을 뿐입니다. 서버도 계정도 필요 없습니다.

## 구현

1. **`tools/build.mjs`**
   - `data/characters.json`을 인라인할 때 `secret` 필드를 제거
   - `web/secrets.json`을 별도 생성: `{ "이든": "...", "세라": "...", ... }`
   - 빌드 후 자체 검사: 산출물 `index.html`에 `characters.json`의 어떤 `secret`
     문자열도 포함되지 않을 것. **위반 시 종료 코드 1** (외부 URL 검사와 같은 방식)

2. **`web/src/data.js`** — `PREGENS[].secret`이 없을 수 있음을 전제로.
   런타임에 주입되는 비밀은 별도 맵(`SECRETS`)으로 둡니다.

3. **`web/src/ui-net.js`** — GM 화면에 "비밀 파일 불러오기(secrets.json)" 추가.
   불러오지 않았으면 "비밀 미로드 — 플레이어에게 전달되지 않습니다" 배지 표시.

4. **`web/src/net.js`** — 방송 시 각 수신자에게 **그 사람이 점유한 캐릭터의 비밀만**
   포함. 명세 03이 `notes`에 대해 이미 하고 있는 것과 같은 필터를 `secret`에도 적용.

5. **명세 01이 남긴 렌더링 차단은 그대로 두세요.** 이중 방어입니다 —
   GM 화면에서 남의 시트를 열었을 때 실수로 보이는 것도 막아야 합니다.
