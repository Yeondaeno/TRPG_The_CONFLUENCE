# 02. 판정 엔진 — 4단계 결과 · 그룹 판정 · 상태 자동화

**선행 조건**: 명세 01 완료 (`rules.js` / `ui-check.js` 껍데기와 호출 지점이 존재해야 함)
**소유 파일**: `web/src/rules.js`, `web/src/ui-check.js`, `tools/test.mjs`

> `app.js` · `ui.js` · `store.js` · `net.js`는 **수정하지 마세요.** 명세 03이 동시에
> 진행 중일 수 있습니다. 수정이 꼭 필요하다면 멈추고 이유를 보고하세요.

## 왜 이게 최우선인가

현재 도구의 주사위 탭은 `2d8 [5,3] +2 = 10`만 출력합니다.
그런데 이 시스템의 간판 규칙은 **1.4 결과의 4단계**입니다 — 규칙서에 없는 행동도
5초 안에 판정하는 절차이고, "부분 성공"이라는 중간 지대가 이야기를 굴리는 엔진입니다.

지금은 그걸 GM이 **매 판정마다 암산**합니다. 8인 파티에서 그룹 판정(1.5)까지 손으로 셉니다.
**이 명세가 끝나야 이 도구가 종이보다 나아집니다.**

## 1. `rules.js` — 순수 함수 계층

전부 부수효과 없는 순수 함수여야 합니다. `RULES`(= `data/rules.json`)를 읽되
수치를 하드코딩하지 마세요.

### `resolve({ natural, total, dc })`

`RULES.outcomeTiers`를 따릅니다.

| 결과 | 조건 |
|---|---|
| `crit` 대성공 | 자연 20 **또는** `total >= dc + 10` |
| `success` 성공 | `total >= dc` |
| `partial` 부분 성공 | `total >= dc - 4` |
| `fail` 실패 | 자연 1 **또는** `total <= dc - 5` |

> **규칙서의 모호한 지점**: 자연 1이면서 `total`이 `dc-1`인 경우, 1.4 표의
> "자연 1 → 실패"와 "DC-1~DC-4 → 부분 성공"이 동시에 성립합니다.
> **자연 1을 우선**하세요 (실패). 자연 20도 마찬가지로 다른 조건보다 우선합니다.
> 이 판단을 코드 주석과 UI 툴팁 양쪽에 남기세요 — GM이 다르게 재정할 수 있어야 합니다.

`natural`은 **d20 굴림에만** 의미가 있습니다. `2d6` 같은 굴림에는 자연 20/1 개념이
없으므로 `natural`을 `null`로 받고 대성공/실패 특례를 적용하지 마세요.
(현재 도구는 2d6을 굴려도 자연 20 판정을 시도할 여지가 있습니다.)

### `modifiers(character, skillId)`

**이 함수가 이 명세의 핵심 가치입니다.** 캐릭터 상태를 이미 저장하고 있으니
보정치를 사람이 손으로 입력할 이유가 없습니다.

반환: `[{ label, value, source }]` 배열. 다음을 자동 산출하세요.

| 보정 | 근거 | 비고 |
|---|---|---|
| 능력치 | 기술의 관련 능력치 (`RULES.skills[].abilities`) | 능력치가 둘이면 **높은 쪽**을 쓰고 UI에 어느 쪽인지 표시 |
| 숙련 +2 | 캐릭터 `skills`에 해당 기술 포함 시 | `RULES.check.proficiencyBonus` |
| 부상 | 중상이면 -2 | `RULES.combat.woundTiers[].checkModifier` |
| 위상잔향 | 25/50/75 임계치 -1/-2/-3 | **신체 능력치 판정에만** 적용 (아래 주의) |

> **주의**: 룰북 3.1은 잔향 페널티를 *"모든 **신체** 능력치 판정"* 에 건다고 씁니다.
> `rules.json`의 `resonance.thresholds[].scope`가 `"physical"`인 이유입니다.
> 어느 능력치가 신체인지 룰북이 명시하지 않으므로 **STR/AGI/CON을 신체로 간주**하고,
> 그 판단을 주석에 남기세요. INT/WIS/CHA 판정에는 잔향 페널티가 붙지 않습니다.

기술명 불일치([errata R-5](../errata.md#r-5-기술명-표기-불일치))가 있습니다 —
캐릭터시트의 `기계정비`·`추적/관찰`·`협상`이 기술 표에 없습니다.
`rules.json`의 `skills[].aliases`로 최대한 매칭하되, **매칭 실패 시 임의로 추측하지 말고**
"이 기술은 표에 없습니다 — 능력치를 직접 고르세요"로 UI에서 GM에게 넘기세요.
데이터를 고쳐서 맞추려 들지 마세요.

### `groupResult(results)`

룰북 1.5. `results`는 각자의 `resolve()` 결과 배열.
- 절반 **이상** 성공(`crit`/`success`) → `'success'`
- 절반 **미만** → `'partial'`

이상(`>=`)과 미만(`<`)이 맞물려 빈틈이 없습니다. 8인 중 4명처럼 **정확히 절반이면
성공** 쪽입니다 — 경계를 `>`로 구현하면 룰북과 어긋납니다.

조력자 보너스(+2)는 참가자별 `modifiers`에 얹히므로 여기서 다루지 않습니다.

### `woundTier(hp, maxHp)` / `resonanceEffect(value)`

`RULES.combat.woundTiers` / `RULES.resonance.thresholds`를 그대로 평가.
경계값을 조심하세요 — 중상은 "50% **미만**", 임계치는 "25 **이상**"입니다.

## 2. `ui-check.js` — 판정 화면

기존 "주사위" 탭을 대체합니다. 목표 화면:

```
[캐릭터: 라비 ▾] [기술: 은신 (숙련) ▾]   vs  DC [12 ▾]  [상황: 불리 -2 ▾]
                                                          [ 판정 ]

  d20 [9] + AGI(+3) + 숙련(+2) + 잔향(-1) = 13   ≥ DC 12
  ────────────────────────────────────────────────────
  성공 — 의도한 대로 이루어짐
```

요구사항:
- 캐릭터를 고르면 기술 드롭다운이 그 캐릭터의 숙련을 위에 정렬해 보여줍니다
- DC는 `RULES.dcTable`을 드롭다운으로(쉬움 8 / 보통 12 / ...) + 직접 입력도 허용
- 상황 보정은 룰북 1.4 절차 2의 `±2~4` 범위 (`RULES.check.situationalDcShift`).
  **DC를 움직일지 굴림에 더할지**는 룰북이 DC 쪽으로 씁니다 — DC를 조정하세요.
- 결과 4단계를 **색과 문구로 명확히** 구분. 각 단계의 처리 방식
  (`RULES.outcomeTiers[].effect`)을 그대로 보여주세요. GM이 외울 필요가 없어야 합니다.
- 자연 20 / 자연 1은 눈에 띄게 표시
- **부분 성공일 때 GM에게 대가를 상기시키세요**: "원하는 걸 얻지만 대가가 따름
  (소음·부상·자원 소모·잔향 획득)". 이게 이 시스템에서 가장 자주 쓰이면서
  가장 자주 잊히는 규칙입니다.
- 보정치 내역을 항상 펼쳐 보이세요. 자동 합산이 **왜** 그 숫자인지 안 보이면
  GM이 도구를 믿지 못하고 결국 손으로 다시 셉니다.
- 기존 자유 주사위(d4~d20, 2d6, 2d8)도 남기세요. 피해 굴림과 잔향 굴림에 필요합니다.

### 그룹 판정

룰북 1.5, 8인 파티의 핵심 장치입니다.

- GM이 "기술 + DC"로 그룹 판정을 **개시**하면 대기 목록이 뜹니다
- 참가자가 각자 굴리면 목록이 채워지고, 전원 완료 시 과반 집계 결과를 표시
- 조력자: 한 명이 먼저 보통(DC 12) 판정에 성공하면 나머지 전원 +2
- **혼자서도 굴릴 수 있어야 합니다** — 네트워크가 없으면 GM이 8명분을 대신
  입력할 수 있는 경로를 남기세요 (P2P 연결은 명세 03이며, 없어도 동작해야 함)

### 상태 자동화

- HP를 바꾸면 부상 단계가 **자동으로** 갱신됩니다 (기존 수동 드롭다운 제거).
  수동 오버라이드는 남기되 자동값과 다르면 표시하세요.
- 잔향이 임계치를 넘으면 경고를 띄우고, 넘긴 순간 **여파화 판정 여부를 GM에게 물으세요**
  (50 이상은 장시간 휴식마다 판정). 조용히 숫자만 올리면 이 규칙은 세션에서 사라집니다.
- 여파화 `d10` 굴림 버튼 → `RULES.resonance.mutationTable`에서 결과를 뽑아
  캐릭터에 부착하고 로그에 남깁니다. 10번은 "GM 재량"이므로 직접 입력을 받으세요.

## 3. 테스트 (`tools/test.mjs`)

`node:test`로 `rules.js`를 검증합니다. 브라우저 없이 돌아야 하므로
`rules.js`가 Node에서도 로드 가능해야 합니다 (파일 끝에
`if (typeof module !== 'undefined') module.exports = Rules;` 정도면 충분).

반드시 포함할 경계 케이스:

| 입력 | 기대 |
|---|---|
| `natural:20, total:5, dc:20` | `crit` — 자연 20은 총합과 무관 |
| `natural:1, total:30, dc:12` | `fail` — 자연 1은 총합과 무관 |
| `natural:1, total:11, dc:12` | `fail` — 자연 1이 부분 성공보다 우선 |
| `total:22, dc:12` | `crit` — DC+10 |
| `total:21, dc:12` | `success` — DC+9는 대성공 아님 |
| `total:12, dc:12` | `success` — 경계 |
| `total:8, dc:12` | `partial` — DC-4 경계 |
| `total:7, dc:12` | `fail` — DC-5 경계 |
| `natural:null` (2d6 굴림) | 자연 20/1 특례 미적용 |
| `woundTier(11, 22)` | `serious` — 정확히 50%는 "50% 미만"이 아님 → `light` 확인 |
| `resonanceEffect(25)` | -1 — "25 이상" 경계 |
| `resonanceEffect(24)` | 없음 |
| 그룹 4/8 성공 | `success` — 정확히 절반은 "절반 이상"에 포함 |
| 그룹 3/8 성공 | `partial` — 절반 미만 |

`woundTier(11, 22)`는 정확히 50%입니다. 룰북은 경상을 "50% 이상"으로 쓰므로
**`light`가 정답**입니다. 테스트로 못 박으세요.
