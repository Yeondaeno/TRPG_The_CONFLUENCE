# ADR-002. GM 보조 도구에서 플레이 가능한 게임으로

- 상태: **채택**
- 뒤집는 것: 이 저장소가 지금까지 전제해 온 "사람 GM이 진행하고 도구가 돕는다"
- 관련: [ADR-001](001-p2p-sync.md)(그대로 유효), [roadmap](../roadmap.md)

## 무엇이 잘못됐나

업로드된 원본 `합경_웹도구.html`은 **세션 도구**였습니다. 캐릭터시트 뷰어 +
주사위 굴림기. 저장소를 세우면서 그 틀을 한 번도 의심하지 않고, 명세 01~06을
전부 "GM이 진행을 편하게 하는" 방향으로 키웠습니다.

판정 엔진도, 시나리오 패널도, 조합도 — 전부 **GM의 손을 덜어주는** 기능입니다.
씬의 NPC를 트래커에 한 번에 투입하는 것이 "핵심 가치"라고 적기까지 했는데,
그건 GM이 문서를 보며 진행한다는 전제 위에서만 가치가 있습니다.

사용자가 원한 것은 **게임**이었습니다. 들어가면 이야기가 굴러가고, 선택지를
고르고, 결과가 갈리는 것 — 발더스 게이트 쪽입니다.

> "이거는 그냥 TRPG 보조같아"

맞는 지적입니다. 한 번도 "이걸 사람 GM 없이 플레이하고 싶으신가?"를 묻지 않은
것이 원인입니다. 원본 자료의 형태가 곧 목표라고 넘겨짚었습니다.

## 결정

**시나리오 데이터가 구동하는 플레이 가능한 CRPG로 전환한다.**
사람 GM은 선택 사항이 되고, 기본은 혼자 플레이다.

```
지금 (GM 보조)                    앞으로 (플레이 가능)
─────────────────────            ─────────────────────
GM이 문서를 읽고 각색             씬 내러티브를 화면이 보여줌
GM이 판정을 요구                  선택지를 고르면 자동 판정
GM이 결과를 해석                  4단계 결과가 분기로 이어짐
GM이 NPC를 트래커에 투입          전투가 자동으로 시작되고 적이 행동함
```

### 왜 "미리 쓰인 분기"가 먼저인가

AI GM(LLM이 그때그때 서술·판정)이 룰북 1.4의 '창의적 행동' 정신에는 더
가깝습니다. 그런데 먼저 하면 이 도구가 지금 가진 가장 좋은 성질을 잃습니다 —
**파일 하나, 외부 요청 0개, 오프라인 동작.** API 키와 네트워크와 비용이 붙습니다.

미리 쓰인 분기로 먼저 완성하면:
- 지금의 배포 방식(HTML 파일 하나)이 그대로 유지된다
- 이야기가 **결정적**이라 테스트할 수 있다 — AI 서술은 검증 자체가 어렵다
- AI GM은 나중에 **선택 기능**으로 얹으면 된다. 반대 순서로는 못 한다

## 버리지 않는 것

명세 01~06이 헛일이 아닙니다. CRPG의 하부 구조가 이미 다 있습니다.

| 기존 자산 | CRPG에서의 역할 |
|---|---|
| `Rules.resolve` / `modifiers` | 선택지 판정을 그대로 해결 — 재작성 없음 |
| `data/characters.json` 16종 | 플레이어 캐릭터 + 동료 |
| `data/scenarios/station-0.json` | Act·씬 뼈대, NPC 스탯, 잔향 곡선 |
| `store.js` 키 분리 | 세이브 슬롯의 기반 |
| P2P (ADR-001) | 여럿이 같이 플레이 |
| 비밀 분리 빌드 (명세 04) | 남의 캐릭터 비밀을 스포일러 없이 유지 |

**그리고 결정적으로**, 시나리오 문서에 씬마다 이미 이렇게 쓰여 있습니다:

```
| 접근 (판정 · DC) | 성공 | 부분 성공 | 실패 |
| 진정·설득 CHA · DC 12 | 증언 전부: "벽이 열리고…" | 증언 절반 + 발작 | 발작 — 전투 태세 |
```

**이건 이미 선택지와 분기 결과입니다.** 사람이 읽으라고 쓴 표일 뿐 구조는
CRPG 그 자체이고, 데이터로 옮기면 그대로 게임이 됩니다. Fable이 시나리오를
쓸 때 "해법 최소 2가지"와 "실패해도 멈추지 않게"를 원칙으로 삼은 것이
결과적으로 분기 설계가 됐습니다.

## 새로 필요한 것

1. **씬 내러티브** — 지금 문서는 "GM이 읽고 각색하라"는 지시문입니다.
   플레이어에게 그대로 보여줄 문장이 없습니다.
2. **진행 상태 머신** — 현재 씬, 플래그, 방문 기록, 분기 조건
3. **전투** — 지금은 트래커만 있고 **적이 행동하지 않습니다**
4. **세이브/로드** — 3~4시간짜리를 한 번에 끝내지 않습니다

## 감수하는 대가

- **이야기가 유한합니다.** 「역참-0」한 편이고, 새 이야기는 사람이 써 넣어야
  합니다. AI GM 층이 나중에 이걸 완화합니다.
- **8인 파티 전제와 충돌합니다.** 룰북과 시나리오는 8명이 각자 캐릭터를
  잡는 전제인데, 혼자 플레이하면 나머지는 AI가 조종하는 동료가 됩니다.
  동료를 몇 명으로 할지, 그들이 판정에 어떻게 참여할지 결정이 필요합니다.
- **1.4 '창의적 행동'이 좁아집니다.** 규칙서에 없는 행동을 5초 안에 판정하는
  것이 이 시스템의 간판인데, 미리 쓰인 선택지는 그걸 못 합니다.
  **이게 AI GM 층을 나중에 반드시 해야 하는 이유입니다.**

## 순서

1. **[명세 07](../specs/07-play-engine.md)** — 씬 스키마 + 진행 엔진 + 플레이 화면.
   씬 하나(1-1)만 완전히 플레이 가능하게 만들어 **구조를 먼저 증명**한다
2. 시나리오 전체 콘텐츠 작성 (11개 씬)
3. 전투 — 적이 행동하는 턴제
4. 세이브/로드, 동료 시스템
5. AI GM 모드 (선택 기능)

1번을 먼저 하는 이유: 씬 11개를 다 쓴 뒤에 스키마가 틀렸다는 걸 알면
전부 다시 써야 합니다. 하나로 증명하고 나서 양산합니다.
