# ADR-003. AI GM은 사용자 계정 연동(BYOK)으로 붙인다

- 상태: **채택**
- 대체하는 것: "작은 모델을 내장한다"는 안
- 관련: [ADR-002](002-playable-game.md)

## 맥락

[ADR-002](002-playable-game.md)는 미리 쓰인 분기로 게임을 만들되, 룰북 1.4의
'창의적 행동'("가로등의 결계 배선을 끊어 적을 감전시킨다")은 미리 쓰인
선택지로 살릴 수 없으므로 AI 층이 나중에 필요하다고 적었습니다.

그럼 그 AI를 어디서 구하는가. 세 가지를 검토했습니다.

### 검토 1 — 작은 모델을 내장한다

| | 크기 | 현재 대비 |
|---|---|---|
| 현재 `index.html` | 318 KB | — |
| Qwen2.5-0.5B (4bit) | ~400 MB | 1,300배 |
| Llama-3.2-1B (4bit) | ~800 MB | 2,600배 |
| 한국어 특화 2~3B (4bit) | 1.5~2 GB | 5,000배 |

브라우저 내 추론(WebLLM + WebGPU)은 기술적으로 가능하지만:
- 첫 실행에 수백 MB를 받아야 하고 WebGPU가 필요합니다
- **"파일 하나 받아서 열면 끝"이 사라집니다** — 이 도구의 가장 좋은 성질
- 0.5B급 한국어 서술은 반복적이고 앞뒤가 안 맞습니다. 실용 하한이 1.5~3B인데
  그것도 규칙 판정은 계속 틀립니다

### 검토 2 — 직접 학습하거나 파인튜닝한다

- **처음부터 학습**: 수천 GPU-시간 + 수백 GB 텍스트. 논외입니다.
- **LoRA 파인튜닝**: 우리가 가진 자료가 룰북+캐릭터+시나리오 다 합쳐 **50KB
  남짓**입니다. 문체 학습에는 최소 수천 개 예시가 필요합니다. 50KB로 튜닝하면
  그 문장들을 외워서 뱉습니다.

### 검토 3 — 사용자 계정 연동 (채택)

사용자가 **자기 API 키**를 넣고, **자기가 쓰는 모델**을 고릅니다.

## 결정

**BYOK(Bring Your Own Key) 다중 공급자 연동.**
Claude · ChatGPT · Gemini · Grok · DeepSeek · Kimi 등에서 고릅니다.

| | 내장 모델 | BYOK |
|---|---|---|
| 배포 크기 | +400MB~2GB | **+~15KB** (어댑터 코드만) |
| 품질 | 소형 모델 수준 | **사용자가 고른 최신 모델** |
| 비용 | 없음 | 사용자 계정에서 나감 |
| 오프라인 | 가능 | 불가 (키 없으면 게임은 그대로 동작) |
| 프라이버시 | 완전 로컬 | 공급자에게 전송됨 |

핵심은 **키가 없어도 게임이 100% 동작한다**는 것입니다.
ADR-001의 P2P 원칙과 같은 구조입니다 — AI는 **얹는 층**이지 기반이 아닙니다.

```
1층  규칙·상태·분기      코드          항상 동작. 오프라인. 318KB
2층  자유 행동 해석      키워드 파서    +~60KB. 키 없이도 동작
3층  서술·즉흥 판단      BYOK API      선택. 키 넣은 사람만
```

## 반드시 지킬 것

### 규칙 판정은 절대 AI에게 맡기지 않는다

이게 이 ADR에서 가장 중요한 줄입니다.

LLM은 산술과 규칙 일관성에서 신뢰할 수 없습니다. d20을 굴리고 보정을 더하고
DC와 비교하는 일은 **이미 코드가 정확하게 합니다**(`Rules.resolve`).
AI에게 넘기면 같은 상황에서 다른 답이 나오고, 플레이어는 그걸 즉시 알아챕니다.

| 일 | 누가 |
|---|---|
| 주사위 굴림 | **코드** |
| 보정 합산 | **코드** |
| 4단계 판정 | **코드** |
| 상태 변경(잔향·HP·플래그) | **코드** |
| 어느 기술·DC로 판정할지 **제안** | AI (사람이 확인) |
| 결과를 문장으로 **서술** | AI |

AI는 **판정 결과를 받아서 묘사할 뿐** 결과를 정하지 않습니다.

### 키는 브라우저를 벗어나지 않는다

- `localStorage`에만 저장. 세션 상태(P2P)로 **절대 전송하지 않습니다**
- 공급자 API로 직접 호출 — 우리 서버는 없고, 만들지도 않습니다
- 화면에 경고를 답니다: 공유 PC에서는 넣지 말 것, 게임 내용이 공급자에게 전송됨

### 브라우저에서 직접 호출한다 (프록시 없음)

프록시 서버를 두면 인프라가 생기고 "파일 하나" 원칙이 깨집니다.
그래서 **CORS를 허용하는 공급자만** 1차 지원합니다.

- Anthropic: `anthropic-dangerous-direct-browser-access: true` 헤더 필요
- OpenAI · Gemini: 브라우저 직접 호출 허용
- DeepSeek · Kimi · Grok 등: 다수가 **OpenAI 호환** 엔드포인트라 어댑터 하나로 커버
- **커스텀 base URL 입력란**을 두어 목록에 없는 공급자·로컬 서버(Ollama,
  LM Studio)도 꽂을 수 있게 합니다

CORS가 막힌 공급자는 **정직하게 "브라우저에서 직접 호출할 수 없습니다"라고
표시**하고 목록에서 비활성화합니다. 되는 척하고 실패하는 게 최악입니다.

## 감수하는 대가

1. **공급자 API는 변합니다.** 어댑터가 깨질 수 있고, 그때 게임은 조용히
   1·2층으로 떨어져야 합니다. 오류로 세션을 막지 않습니다.
2. **비용이 사용자에게 갑니다.** 씬 하나에 몇 백 토큰이면 원샷 한 판이
   몇 십 원 수준이지만, 명시해야 합니다.
3. **검증이 어렵습니다.** AI 서술은 매번 다릅니다 — 테스트는 "호출이 나가고
   응답이 파싱되고 실패 시 폴백한다"까지만 하고, **문장 품질은 검증하지
   않습니다.** 못 하는 걸 하는 척하지 않습니다.
4. **게임 내용이 제3자에게 전송됩니다.** 프라이버시 경고가 필요합니다.

상세 구현은 [명세 09](../specs/09-byok-ai.md).
